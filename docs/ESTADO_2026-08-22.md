## 2. Closed and Verified in This Session

### Security

| code | what it was |
|---|---|
| **K-C20** | **RWX page reachable from ring 3.** ELF loader flag derivation was binary: writable → RW, *everything else* → **RX**. A `PF_R` segment without `PF_X` was mapped executable, and combined with the page reuse branch resulted in **R+W+X**. W^X broken by an image the loader accepts as valid. |
| **K-C18** | **Ring 3 jumping to kernel code.** `sret_to_user` zeroed only `a0`–`a7`; every process entered with `ra`, `gp`, `t*`, and `s*` full of kernel garbage. Layout leak *and* crash. K-C11 had made it inheritable to the child of `fork`. |
| **K-C16** | **Ring 3 imposing its hart id on the kernel** via `tp`. Closed with per-hart trap vectors indexed by `stvec`: +3 instructions on U-mode entry, 0 on S-mode traps. |
| **K-C16b** | `trap_return` undid the K-A11 migration when returning to S mode. |
| **IPC-1..6** | The six ownership gates of the IPC subsystem: server impersonation, false `Replied`, TID validation, reclamation in `task_exit`, owner in leases, and slot ABA. |
| **K-C5** | **Mandatory encryption mode** on the brain link. User decision. Per-packet gate, compile-time policy. |
| — | Zero page ceased to be demandable; ELF loader gained lower bound on `p_vaddr` and segment order check; `sys_mmap` and `sys_alloc_demand` no longer return null base as success. |

### Correctness and Performance

| code | what it was |
|---|---|
| **K-C12** | Children of `fork()` that never ran. **It was not `fork`**: it was CPU placement. `find_least_loaded_cpu` counted *queued* tasks, blind to the running task and priority. 98 of 98 children executed on a hart with no RT residents; 0 of 5 on the two that had them. |
| **K-C14** | All wakeups without affinity went to CPU 0 — where real-time tasks live. Reproducible victim starvation. |
| **K-C15** | Cross-CPU wakeups did not ring the bell: enqueuing on another hart did not notify that hart, and with tickless scheduling its next timer could be far away. |
| **K-C17** | `state` and `wait_reason` published in broken order: a waker could see `Blocked` with the reason not updated and **release the wakeup without leaving a stamp**. |
| — | Boot hart is not always 0 (measured: 2). `wake_harts` accounting assumed it; **only broke if some `hart_start` also failed**, which is why it was never seen. |
| — | `cpu_enqueue` protected overflow with `debug_assert!`, compiled out in release. Duplicates were real and frequent. |
| — | `SYS_IPC_CALL` published the request before registering for the reply; `SYS_IPC_LEASE_ACCEPT` blocked the lessee on a reason nobody ever woke; `SigTable::get_or_create` returned index 0 with the table full, aliasing the signal state of every task past 64 — and failed **open**. |
| — | `FAST_ACCEPT` did not deliver the request to ring 3 despite promising it in its comment: fast-IPC was not a usable RPC transport. |
| — | The fault handler printed **before** attempting to resolve, so every COW fault read as fatal. 3 blocks → 0. |
| — | `lease_tick` **measured by counting instructions in the RV64 binary**: extending to `Pending` costs **zero** (adjacent discriminants, a single `bgeu`). The real cost (+8 fixed instructions) was `lock()` → `lock_irqsave()`. |

## 3. What Remains Open

### Blocker

> **CLOSED 23-08**: state and stamp packed in a single `AtomicU32` per task
> with symmetric conditional CAS — see the "K-C19 — CLOSED" section of
> [`IPC_AUDIT_2026-08-22.md`](IPC_AUDIT_2026-08-22.md) for the design,
> verification (67 host tests running the real protocol, CI 40/40, zero panic
> paths in wakers counted over the RV64 artifact) and what remains for QEMU
> (repeat frequency measurement). The following text is preserved as original
> diagnosis.

**K-C19 — the final stamp window.** `block_current` consumes `wake_pending` and
*then* marks itself `Blocked`. A waker that reads `Running` between those two
operations leaves a stamp already surpassed that nobody will consume. Permanent
sleep, with the wakeup issued and accounted.

Tested by identity, three runs, same signature: the reply deposited in the slot,
addressed exactly to the client sleeping on it. **Frequency ~1 per 3 runs.**

The double-check handshake **was written, worked, and reverted**: caught two
real hangs but introduces a worse race — if the waker wins the stamp `swap` and
enqueues the task while it still heads toward `do_schedule`, the task becomes
both "current" and queued, and the system freezes at boot. **Hanging the board
is worse than losing a wakeup.**

The correct fix requires that state and stamp be read and written under the same
exclusion: one lock per task, or a single atomic with CAS encoding both.
Structural scheduler change, touches all wakers.

### Annotated Findings, Not Closed

>    non-contiguous ids is post-hardware work; the clamp from point 2 makes it
>    safe — out-of-range id is parked, not corrupted).
> 8. `SYS_IPC_FAST_CALL` returns 4 words: a1..a3 via `SyscallOut` (success
>    only), and libsys migrated to a dedicated asm block with `lateout`
>    (`fast_ipc_call_full`; the single-word wrapper preserved on top).
>
> Also: zombie→`context_switch` with `old=NULL` (nothing writes to a freed
> slot), demonstrable guard on the block path (zero panic paths, verified in
> the binary), `signal_send` confirmed authorized (self-or-privileged, rail D),
> and the `handle_owned_by` comment re-tagged as historical with current
> numbers.
>
> The following text is preserved as original diagnosis.

1. **Camera frames do not pass through the envelope.** `PKT_CAMERA` goes
   straight by TCP, no envelope and no AEAD, guarded by `link.is_none()` —
   triggers **precisely when there is no session**. Today, even with a key
   loaded, they travel unauthenticated.
2. **`PER_CPU` without clamp.** It is `[_; MAX_CPUS]` with `MAX_CPUS = 4`, all
   access is `PER_CPU[current_cpu_id()]`, and `boot.S` only checks range on
   *secondary* harts. On a board enumerating more harts than `MAX_CPUS` — the
   VF2/JH7110 case already documented — a boot hart 4 indexes out of range and
   **resets the board**.
3. **The race at the bottom of `idx_for_tid`.** Unsynchronized scan *can*
   return the wrong slot; today it is not reachable from ring 3 because all
   entry points pass `current_task_tid()`. `SYS_CAP_GRANT` is exactly what
   would make it reachable, and that is why it carries its own revalidation.
   `OWNER` prevents theft but not **destruction**: an operation attributed to a
   dead TID landing in a live slot empties its capability table.
4. **Cap table exhaustion DoS.** Any task with a delegable cap can fill all
   256 slots of any live task.
5. **`find_best_cpu` returns hart 0 hardcoded** when only one is alive, and the
   doc for `rebalance_from_offline_cpus` claims something false for a live hart
   past a gap.
6. **The client side of the fast-IPC ABA.** `WaitReason::FastIpcClient(u32)`
   carries the raw index; `fast_ipc_wait_state` contains it, does not eliminate
   it.
7. **`wake_harts` still assumes contiguous hart ids.**
8. `SYS_IPC_FAST_CALL` returns a single word of reply.

## 7. Traps in This Tree, for Whoever Resumes

All bit at least once in this session.

- **Cargo does not track `.ld` or `.S`.** `make` prints "Built" and reuses the
  old binary. Verify the actual `PT_LOAD` headers, or `strings` on the ELF.
- **`target/` and `build/` are shared state across rails.** One agent's build
  overwrote the kernel another was about to boot, and the guest failed with an
  unrelated error. Copy kernel and image to scratchpad and boot from the copies.
- **The guest writes to FAT32.** Regenerate the image on each run or you measure
  the machine's history.
- **Wall-clock thresholds under QEMU lie.** A WCET false positive of 36 events
  vs 3 turned out to be host load: the same binary repeated at rest gave 1. To
  judge cost, **count instructions in the RV64 binary**.
- **Context-switch trace hides races.** Six UART writes per switch move timing
  enough: with `ipc-trace` phase A passes 8/8 where without it it hangs. That is
  why `ipc-census` exists, deliberately independent.
- **An optimistic `Status:` costs more than a bug.** The secure-boot scenario
  passed **without running Ed25519**, for different reasons on different
  machines.
- **A test that hand-replicates the logic it monitors monitors nothing.** Three
  were removed from `regression-tests` that tested a private copy of
  `find_least_loaded_cpu` and kept passing green asserting the abandoned
  policy.
